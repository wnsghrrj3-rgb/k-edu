# 설계 — K-edu 교사 인증 체계 v1.1 (2026-08-27 확정)

> v1.1: 나이스 문서확인번호 문을 **보류**로 격하 — 운영자가 진위확인을 일상 루틴으로 돌리기 어렵다는 판단(준호).
> 정식 문은 교육청 메일 하나. 교육청 메일이 없는 교사는 신청 메모를 남기고 운영자 재량 수동 승인(아는 교사 등).

> 목적: 케이에듀를 "교사에게만 열리는 수업 무기"로 유지하기 위한 인증·승인 체계의 단일 기준 문서.
> 코드·SQL·운영 절차가 전부 이 문서와 일치해야 한다. 바꿀 때는 문서를 먼저 고친다.

---

## 0. 제품 원칙 (이 설계의 뿌리)

1. **모든 기능은 교사가 열어줘야 작동한다.** 학생·학부모가 교사 없이 단독으로 쓸 수 있는 기능은 만들지 않는다.
2. **인증의 단위는 교사 개인.** 남의 보증(초대 코드)이 아니라 본인 증명만 인정한다 — 초대 코드는 도입하지 않기로 확정.
3. **유료화는 교사의 「열기 권한」에만 붙는다.** 학생 쪽 코드는 과금과 무관하게 유지된다.
4. **개인정보는 최소로.** 증빙 서류는 받지도 보관하지도 않는다 — 번호로 진위만 확인한다.

## 1. 상태 기계

teachers.approval — 4상태. 트리거가 정하고, 관리자와 정해진 통로만 바꾼다.

```
                      가입(teachers INSERT, 트리거①)
                              │
        스위치 ON + 교육청 메일 │ 그 외
                 ┌────────────┴───────────┐
                 ▼                        ▼
               auto ◄────────────────  pending
             (자동승인)   claim RPC      (대기)
                 │      (스위치 ON +      │  관리자 승인
                 │       교육청 메일)     ▼
                 │                     approved
                 │                        │
                 └────────┬───────────────┘
                          │ 관리자 반려
                          ▼
                       rejected  ──(관리자만 복구)──▶ pending/approved
```

- **auto**: 교육청 메일 자동승인. 가입 순간(트리거①) 또는 접속 시 소급(claim_edu_auto_approval).
- **pending**: 가입만 된 상태. 교사 공간 화면·학급 발급·슬롯·박스 전부 잠김.
- **approved**: 관리자(준호) 수동 승인.
- **rejected**: 반려. 교육청 메일로도 못 뒤집는다 — 관리자만 해제.

## 2. 승인의 문 — 두 개뿐

| 문 | 증명 | 처리 | 근거 강도 |
|---|---|---|---|
| ① 교육청 메일 | 시도교육청 도메인 메일의 소유 (Supabase Confirm email) | 자동 (스위치 ON 시) | 강함. 단, 일부 교육청(서울 확인됨)은 학생·행정직도 같은 도메인 계정을 발급 — 100% 교사 보장은 아님을 인지하고 운영 |
| ② 신청 메모(보류 상태의 예비 문) | 학교명·직위 신청 | **수동** — 운영자 재량(아는 교사·직접 확인 가능한 경우만) | 재량. 나이스 문서확인번호 방식은 v1.1에서 보류 — 운영 루틴으로 부적합 판정 |

### 2-1. 나이스 번호 자동 승인은 하지 않는다 (판정)

- 나이스 진위확인에는 **공개 API가 없다.** 자동화하려면 정부 시스템 화면을 기계로 조작해야 하는데, 캡차·개편에 취약하고 정부 시스템 약관과 충돌 소지가 있어 채택하지 않는다.
- **번호 "형식"만 검사해 자동 승인하는 것은 금지.** 형식이 맞는 가짜 번호는 누구나 만들 수 있다 — 이건 벽이 아니라 벽 그림이다.
- "일단 자동 승인 + 사후 확인" 모델도 채택하지 않는다. 확인 전 공백 동안 학급을 만들고 학생 데이터를 모을 수 있어, 사후 반려로는 되돌릴 수 없는 노출이 생긴다.
- 결론: ②는 수동이 맞다. 대신 운영 마찰을 줄인다 — 관리자 대기 표에 번호 강조 표시(적용됨), 향후 번호 복사 버튼·진위확인 바로가기 추가.

## 3. 잠금 지점 전수 (심층 방어 — 한 겹이 뚫려도 다음 겹이 막는다)

| 겹 | 지점 | 구현 | 상태 |
|---|---|---|---|
| 화면 | 교사 공간 전면(케이티처 52면·케이플/케이배틀 호스트·라이브 교사·케이랩 교사 허브·케이박스 관리) | kedu_teacher_gate.js — 세션+approval 판정, 5분 캐시, 상태별 잠금 카드 | 적용 (2ae3c26) |
| 화면 | 교사 대시보드(/teacher/) | 로그인만 요구 — **대기 상태도 입장 가능해야 신청을 한다** (의도적 예외) | 유지 |
| DB | class_codes INSERT | RLS: 본인 + kedu_teacher_approved() | 적용 (#23) |
| DB | class_codes UPDATE | RLS: 본인 + (끄기 또는 승인) / 동의 다운그레이드는 트리거 금지 | 적용 (#27) |
| DB | student_seats INSERT | 트리거: created_by 교사가 승인 상태 아니면 거부 (DEFINER RPC 우회 불가) | 적용 (#27) |
| DB | cw_bundles/items/sends, ma_routines, class_openings | RLS WITH CHECK 에 승인 조건 | 적용 (#23·#25) |
| DB | teachers.approval/is_admin 셀프 조작 | 트리거②: 비관리자 변경 되돌림 (claim 전용 통로만 예외) | 적용 (#23·#27) |
| 정책 | 자동승인 스위치 | kedu_policy.auto_approve_edu_domains — 관리자 RPC로만 변경 | 적용, 현재 **OFF** |

## 4. 데이터

- `teachers`: approval / approved_at / approved_by / approval_note(신청 메모 = "학교·직위 | 나이스증명 {번호}") / approval_requested_at
- `edu_domains`: domain(PK) / region / active / verified — 17개 시도. **verified=true 는 "실물 교사 메일로 확인함" 뜻.** 하위 도메인 자동 매칭(x.sen.go.kr).
- `kedu_policy`: auto_approve_edu_domains (false=1단계 수동, true=2단계 자동)
- 나이스 문서확인번호는 approval_note 안 텍스트로만 저장 — 별도 컬럼·검증 상태를 만들지 않는다(번호 자체는 비밀값이 아니고, 확인 결과는 approval 상태가 곧 기록).

## 5. 운영 절차 (준호 루틴)

1. **대기 알림 확인**: /admin → 승인 대기 표. 「교육청」 배지가 있으면 메일만으로 판단 가능.
2. **나이스 확인 (30초)**: 신청 메모의 파란 번호 → 나이스 대국민서비스 「증명서 진위확인」에 입력 → 발급 사실 확인 → [승인].
3. **의심스러우면 반려**: 반려 사유는 남기지 않아도 됨 — 교사 화면에 재신청 안내가 뜬다.
4. **도메인 검증**: 아는 선생님의 실물 교육청 메일을 볼 때마다 해당 지역 `verified=true` 로 갱신. **스위치 ON 은 최소 준호 본인 지역 1곳 실검증 후.**
5. **연 1회(3월) 정리**: 재직은 "발급 시점" 증명이므로 퇴직·휴직자는 걸러지지 않는다. 매년 3월 연간 초기화 때 장기 미접속 승인 계정을 훑는 것으로 수용(당장 자동화하지 않음 — 규모가 생기면 재설계).

## 6. 남은 실행 순서 (이 순서대로만)

1. [준호] Supabase: `UPDATE edu_domains SET domain='gbe.kr' WHERE domain='gbe.go.kr';` (경북 수정)
2. [준호] Supabase Auth: **Confirm email ON 확인** — OFF 인 채 스위치를 켜면 남의 교육청 주소 도용으로 자동승인이 뚫린다. 스위치 ON 의 전제조건.
3. [준호] 시험 A (일반 메일 코스): 가입 → 이름·학교 칸 노출 → 메일 확인 → 잠금 카드(케이티처 포함) → 신청(학교·직위 + 나이스 번호) → /admin 확인·승인 → 열림
4. [준호] 시험 B (교육청 메일 코스): 스위치 ON → 교육청 메일 가입 → 확인 → 접속 즉시 열림 (배너 없이)
5. [준호] 시험 계정 반려 → ⛔ 반려 화면 확인 → 계정 정리
6. [클로드] 시험에서 걸린 것 수정 → 나이스 진위확인의 실제 메뉴 경로를 /admin 안내에 반영

## 7. 이 설계가 금지하는 것 (다시 논의 전엔 불변)

- 초대 코드 및 모든 형태의 "교사가 교사를 보증"하는 통로
- 나이스 번호 형식 검사만으로의 자동 승인
- 증빙 서류 파일 업로드·보관
- 승인 전 계정의 교사 공간 화면 접근 (대시보드 제외)
- 학생·학부모 대상 과금

## 8. 유료화 연동 지점 (설계만, 구현 안 함)

과금 대상 = 교사의 「열기 권한」. 구현 위치는 `open_for_class` / 개방 판정기(KeduTier) 한 곳 — "이 기능 키는 유료 플랜 교사만 열기 가능" 조건을 열기 단계에 붙인다. approval 체계와 독립이며, 이 문서의 상태 기계는 바뀌지 않는다.
