## 1. PROJECT VISION
KEDU WORLD HISTORY는 역사 강의나 문제집을 3D로 옮기는 프로젝트가 아니다. 학생이 역사 속 공간에 직접 들어가 그 시대 사람들의 생활과 문제를 경험하고, 직접 행동하고, 그 결과를 본 뒤 "왜 사람들은 이렇게 살았을까?" "왜 이런 변화가 일어났을까?"를 이해하게 만드는 체험형 3D 역사 학습 세계다.

핵심 문장: **"역사를 외우기 전에 살아본다."**
학생이 최종적으로 느껴야 하는 것: "역사 공부를 했다"가 아니라 "나는 그 시대에 가봤고, 사람들이 왜 그렇게 살았는지 이해한다."

## 2. CORE LEARNING LOOP
경험 → 발견 → 문제 발생 → 행동 → 결과 → WHY → 이유와 인과관계 이해 → 간단한 확인 → 보상 → 다음 경험
- 역사적 사실을 먼저 설명하지 않는다. 가능한 경우 먼저 경험하게 한다. 그 후 "그런데 왜 그랬을까?"를 질문한다.
- 암기보다 변화의 원인과 결과 이해가 핵심.

## 3. GAME DESIGN PRINCIPLE
단순 퀴즈게임이 아니다. 적극 활용할 게임 요소: 3인칭 캐릭터 · 자유 이동 · 탐험 · NPC · NPC 대화 · 사건 · 미션 · 물건 조작 · 아이템 · 인벤토리 · 지도 · 미니맵 · 웨이포인트 · 지역 해금 · 수집 · 보상 · 시대 이동.
목적은 점수 획득이 아니다. 게임 메커니즘 자체가 역사 학습과 연결되어야 한다.
- 조선: 호패→성문 통과 · 엽전→물건 구입 · 지도 조각→새 장소 발견 · 편지→NPC에게 전달
- 구석기: 돌→뗀석기 제작 · 뗀석기→사냥/생활 도구 · 나무→불
**ITEM = REWARD가 아니라 ITEM = LEARNING + INTERACTION.**

## 4. WHY MOMENT
AI나 시스템이 계속 설명하지 않는다. 학생이 충분히 경험한 뒤 이유를 생각할 수 있는 순간에만 개입한다.
예: [잠깐, 생각해 볼까?] "농사를 짓기 시작한 뒤 사람들의 생활에서 가장 크게 달라진 것은 무엇일까?" → 학생이 생각하거나 답한다 → KEDU가 경험과 역사적 개념을 연결한다.
농사를 지으려면 씨앗을 심고 자라기를 기다려야 했다 → 한곳에 머물게 되었다 → 집을 만들었다 → 사람들이 모였다 → 마을이 만들어졌다. 즉 **농경→정착→집→마을**의 인과관계.

## 5. INITIAL HISTORY ROADMAP
초기 목표는 각 시대를 깊게 만드는 것이 아니라 한국사 시작부터 현대까지 한 번 **완주할 수 있는 기본 뼈대**.
| WORLD | 시대 | 핵심 질문 |
|---|---|---|
| 01 | 구석기 | 사람들은 어떻게 살아남았을까? |
| 02 | 신석기 | 왜 사람들은 한곳에 살기 시작했을까? |
| 03 | 청동기·고조선 | 왜 계급, 나라, 법이 생겼을까? |
| 04 | 삼국·가야 | 왜 여러 나라가 경쟁했을까? |
| 05 | 통일신라·발해 | 통일 이후 사회와 공간은 어떻게 달라졌을까? |
| 06 | 고려 | 고려는 어떻게 나라를 지키고 문화를 발전시켰을까? |
| 07 | 조선 전기 | 조선은 어떤 사회와 국가를 만들려고 했을까? |
| 08 | 조선 후기 | 왜 조선 사회는 변하기 시작했을까? |
| 09 | 개항~일제강점기 | 나라가 흔들리는 상황에서 사람들은 어떤 선택을 했을까? |
| 10 | 대한민국 | 오늘날 대한민국은 어떻게 만들어졌을까? |
초기 구조이며 향후 더 세분화할 수 있어야 한다.

## 6. WORLD 01 — PALEOLITHIC (첫 Vertical Slice 후보)
핵심 질문: "사람들은 어떻게 살아남았을까?"
MAP: 동굴 · 숲 · 강 · 사냥터 · 야영지
기본 경험: 숲에서 깨어남 → 부족 NPC 만남 → 먹을 것이 부족하다는 사실 발견 → 돌 발견 → 돌 조작 → 뗀석기 제작 → 열매 채집 → 동물 흔적 발견 → 사냥 → 나무 수집 → 불 사용 → 야영지 복귀
기본 개념: 뗀석기 · 사냥 · 채집 · 불 · 이동생활 · 동굴/막집 · 무리생활
WHY: "왜 구석기 사람들은 한곳에 오래 살지 않았을까?" — 주변의 먹을 것이 줄어드는 것을 학생이 먼저 경험 → 사냥·채집 중심 생활 → 먹을 것 감소 → 새로운 먹을거리 필요 → 이동
대표 아이템: 주먹도끼

## 7. WORLD 02 — NEOLITHIC
핵심 질문: "왜 사람들은 한곳에 살기 시작했을까?"
경험: 씨앗 발견 → 심기 → 기다리기 → 작물 성장 → 수확 → 동물 기르기 → 움집 → 토기 → 마을
기본 개념: 농경 · 목축 · 정착생활 · 움집 · 빗살무늬토기 · 가락바퀴
WHY: "농사를 시작하자 왜 마을이 생겼을까?" — 농경→정착→집→사람들이 모임→마을
대표 아이템: 빗살무늬토기

## 8. WORLD 03 — BRONZE AGE / GOJOSEON
농업 생산량 증가 → 잉여 생산물 → 재산 차이 → 권력 차이 → 계급 → 족장 → 정치 집단 → 나라
학생이 직접 경험: 곡식 저장 · 집마다 다른 재산 · 큰 창고 · 족장 · 고인돌 · 마을 간 갈등 · 물건 도둑/분쟁 · 규칙 필요성
WHY 1: "왜 계급이 생겼을까?" / WHY 2: "왜 나라와 법이 필요했을까?"
대표 아이템: 비파형 동검 · 고조선 법 조각

## 9. LATER WORLDS
- 삼국·가야: 지형·자원·교통·문화·군사·외교를 공간과 지도에서 경험. 핵심: 왜 여러 나라가 경쟁했는가?
- 남북국: 통일신라와 발해를 직접 경험. 핵심: 왜 남북국 시대라고 보는가?
- 고려: 개경 · 시장 · 벽란도 · 고려청자 · 불교 · 외침 · 팔만대장경
- 조선: 한양을 살아있는 역사 공간으로 — 성문 통과 · 호패 · 시장 · 엽전 · NPC 대화 · 궁궐 · 관청 · 백성 생활. **훈민정음**: 읽기 어려운 한자 정보 환경을 먼저 경험 → 불편함 → 새 글자의 필요성 발견 → 훈민정음 → WHY "왜 세종은 새로운 글자가 필요하다고 생각했을까?"
- 조선 후기: 상업 · 화폐 · 서민문화 · 실학 · 농업 변화 · 사회 변화
- 개항~일제강점기: 역사적 사실을 존중. 실제 역사와 가상 선택/사고실험을 명확히 구분 — 📜 HISTORICAL FACT / 🔀 WHAT IF · THINK
- 현대사: 사실·자료·관점을 구분. 특정 정치적 판단을 학생에게 주입하는 방식으로 설계하지 않는다.

## 10. HISTORY BAG
한국사를 여행하며 대표 역사 아이템 수집(구석기 주먹도끼 · 신석기 빗살무늬토기 · 청동기 비파형 동검 · 고려 고려청자 · 조선 훈민정음 …).
단순 도감이 아니다. 아이템을 선택하면 "내가 언제, 어디에서, 무슨 경험을 통해 이 물건을 얻었는가"를 다시 볼 수 있다. **수집 시스템이면서 복습 시스템.**

## 11. CONTENT DEPTH
현재는 각 시대의 "기본 역사 뼈대"만. 모든 내용을 처음부터 넣지 않는다.
예 구석기 초기: 뗀석기 · 사냥 · 채집 · 불 · 이동생활 / 향후 추가: 공동사냥 · 불의 활용 · 석기의 발전 · 당시 기후 · 한반도 구석기 유적 · 고고학적 증거 · 인류 이동 · 생활 방식 심화.
같은 WORLD에 콘텐츠를 계속 추가할 수 있어야 한다.

## 12. LEARNING DEPTH LEVEL
같은 3D WORLD를 여러 학습 깊이에서 사용: LEVEL 1 BASIC(초등 기본) · LEVEL 2 INQUIRY(원인·결과 심화) · LEVEL 3 ADVANCED(환경·경제·생산력·사회구조·고고학 자료·사료·다양한 해석).
새 LEVEL = 새 게임이 아니다. WORLD는 공유하고 콘텐츠와 깊이만 달라진다.

## 13. DATA-DRIVEN CONTENT ARCHITECTURE
역사 콘텐츠를 엔진 코드에 직접 넣지 않는다. 데이터로 분리:
WORLD ├ ERA ├ AREA ├ NPC ├ OBJECT ├ EVENT ├ STORY ├ MISSION ├ INTERACTION ├ ITEM ├ KNOWLEDGE ├ WHY ├ ASSESSMENT ├ REWARD ├ LEVEL └ EXPANSION
새 콘텐츠 추가 시 핵심 엔진을 반복 수정하는 구조를 피한다. 장기 목표: 관리자·교사가 NPC·미션·지식·WHY·아이템·이벤트를 추가해 기존 WORLD를 확장.

## 14. KEDU HISTORY ENGINE
각 시대를 별도 게임으로 만들지 않는다. 공통 엔진 후보 시스템: 3D World · Player Movement · Third-person Camera · Object Interaction · Grab/Move/Use · Collision · Physics · NPC · NPC Dialogue · Quest · Event · Item · Inventory · Waypoint · Map/Mini Map · Quiz/Interaction · WHY Moment · Reward · Area Unlock · Era Transition · Save/Load · Student Progress · Learning Record · AI Interaction.
시대별로 바뀌는 것: Map · 3D Assets · NPC · Mission · Historical Content · Events · Rules.

## 15. VISUAL TARGET
"교육 사이트 같은 3D"가 아니라 "게임 세계에 들어왔다". AAA Photorealism은 목표가 아님.
목표: **HIGH QUALITY STYLIZED REALISM + LIGHTWEIGHT WEB 3D + EXCELLENT INTERACTION**
하나의 디자인 언어로 통일: Character · Environment · NPC · Lighting · Material · Camera · Mission UI · Dialogue UI · Inventory · Mini Map · Waypoint · Reward · WHY UI.

## 16. DEVELOPMENT STRATEGY
- PHASE 1: KEDU HISTORY ENGINE 기본 구조 설계
- PHASE 2: 구석기 약 15분 Vertical Slice — 숲에서 깨어남 → 부족 NPC → 먹을 것 부족 → 돌 발견 → 뗀석기 → 채집/사냥 → 불 → 야영지 → WHY → 주먹도끼 획득 → 신석기 해금
- PHASE 3: 학생 플레이 테스트(재미·조작감·학습 효과·이해도·몰입도)
- PHASE 4: 같은 엔진으로 신석기→청동기→고조선→삼국→남북국→고려→조선→근현대 확장
- PHASE 5: 완주 구조 완성 후 시대별 심화 콘텐츠 지속 추가

## 17. CLAUDE / ASTRA DEVELOPMENT WORKFLOW
두 AI가 같은 파일을 동시에 수정하지 않는다.
CLAUDE = STRUCTURE + FUNCTION (전체 구조·기능·데이터·로직·KEDU 통합·1차 구현) → ASTRA = VISUAL + EXPERIENCE UPGRADE (실행 화면 분석·3D 품질·UI·UX·Camera·Lighting·Material·Animation·Interaction Feel·Visual Polish) → CLAUDE (변경 코드 검토·Regression·KEDU 구조 통합) → 필요 시 ASTRA 재확인.
실제 성능에 따라 역할은 조정 가능.

## 18. PRESERVE EXISTING KEDU
기존 시스템을 무조건 새로 만들지 않는다. 항상 먼저 기존 코드베이스 분석: 재사용 가능 시스템 · 현재 3D 엔진 · Object 구조 · Interaction 구조 · Save 구조 · User/Student 구조 · Learning Record 구조 · API · DB · UI Component. 가능한 것은 재사용. 구조 변경 시 먼저 이유와 영향 분석.

## 19. EXPANSION IS A CORE REQUIREMENT
"계속 자라는 역사 세계". 같은 WORLD에 장소·NPC·역사 인물·사건·문화재·유적·생활·경제·전쟁·외교·사회·미션·탐구·사료·다른 관점·심화학습을 계속 추가. 초기 구현의 가장 중요한 기술 조건 = **EXTENSIBILITY**.

## 20. FIRST PRINCIPLE
기능을 판단할 때 항상: **"학생이 이걸 외우는가, 아니면 직접 경험해서 이해하는가?"** — 가능하면 후자.
케이에듀 상위 철학 유지: "KEDU — 시간을 꿈으로 만드는 곳." / "아이가 이곳에서 보낸 한 시간이 아이에게 무엇으로 남았는가?"
