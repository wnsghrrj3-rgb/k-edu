# 케이히스토리 구조 설계 v1 — 「진짜 게임」까지의 층

> 2026-09-17. 준호 지시: 「너가 혼자 진행할 수 있는 부분 전체 구조 설계, 꼼꼼하게 여러 층」. 상위 원칙은 `KEDU_WORLD_HISTORY_MASTER.md`(종속 금지·태블릿 기준·시대 이름은 발굴에서), 이야기는 `KEDU_HISTORY_STORY_MASTER_v1.md`. 이 문서는 그 아래 **엔진·자산·연출·소리·저장의 층 구조**와 각 층에서 **내가 혼자 만들 수 있는 것 / 준호 손이 필요한 것**을 가른다.
> 오늘(09-16) 확인된 사실: Tripo 「사진→스마트 메시→리깅」 자산이 우리 엔진에 그대로 들어간다(참나무 89그루 인스턴스 · 아루 GLB 대기 동작). 그래서 이 설계는 **「자산은 Tripo, 구조는 코드」** 를 전제로 쓴다.

## 1. 자산층 — 「Tripo 에서 나온 것이 그대로 들어가는」 규격

**폴더·이름**
```
kworld/assets/
  trees/    oak_a.glb  oak_b.glb  pine_a.glb          (나무 — 인스턴스)
  people/   aru.glb  maru.glb  hana.glb  nuri.glb  bara.glb  old.glb  child.glb   (사람 — 뼈대·동작 포함)
  animals/  deer.glb  fawn.glb                       (동물 — 뼈대·동작 포함)
  props/    rock_a.glb  rock_b.glb  shelter.glb  firepit.glb  scraper.glb …   (소품 — 정적)
  manifest.json                                       (자산 대장 — 시험이 읽는다)
```
- 이름은 `<종류>_<변형>.glb`, 소문자, 시대 이름 없음(구석기 참나무도 `oak_a`). 시대별 차이는 `eras/<era>/world.json` 이 어느 자산을 쓰는지로만.
- `manifest.json`: `{ "people/aru.glb": { "tris": 10890, "bones": 41, "clips": ["walk","wait","run"], "height": 1.0, "front": "+z", "source": "tripo smart-mesh 2026-09-16" } }` — 자산이 들어올 때 내가 채운다. 시험이 「clips 에 wait·walk 없음」「tris 예산 초과」를 잡는다.

**크기 규격(태블릿 기준, 넘으면 다이어트)**
| 종류 | 삼각형 | 질감 | 비고 |
|---|---|---|---|
| 나무(인스턴스) | ≤ 12k | 1k webp | 89그루라 12k×89 ≈ 1M — 여기가 상한 |
| 사람 | ≤ 14k | 1k webp | 동시에 7~8명 |
| 동물 | ≤ 10k | 1k webp | 무리 3~4 |
| 소품 | ≤ 6k | 1k webp | 바위는 인스턴스 |
| 영웅 소품(발굴 장면 유물) | ≤ 30k | 2k | 한 번에 하나 |

**다이어트 절차(내 몫, 자동)** — `gltf-transform optimize --texture-compress webp --texture-size 1024 --compress false`(사람·동물은 양자화 끔 — 뼈대 있는 메시는 양자화가 위험) / 나무·소품은 `--compress quantize` 허용(그때 엔진이 int16→float 로 풀어 굽는다, 이미 구현). 196만 면짜리 HD 는 받지 않는다 — **Tripo 리토폴로지·스마트 메시에서 이미 줄어서 오는 것만**(09-16 확인: 내 쪽 감축은 잎이 깨짐).

**Tripo 뽑기 표준(준호 몫)** — 이미지 탭(T포즈/정면) → 멀티 뷰 → 스마트 메시 → 텍스처 1k → (사람·동물) 리깅 → 동작 → 내보내기 GLB·1k·스켈레톤 켬·동작 수 확인. 옷차림 기준은 아루(어깨·몸통·무릎 덮는 가죽 튜닉, 노출 없음). 프롬프트 표는 `STATUS-kedu-world.md` 09-17 항목.

## 2. 세계층 — 바닥이 자산을 받쳐 줘야 한다

지금: 지형 GLB(paleo.glb) + `landscape.js`(나무 GLB 인스턴스 89 · 풀 · 덤불) + `visuals.js`(하늘돔·물·표면 질감 4종).
**신규 ① 바닥 스플랫** — 높이·경사·물 거리로 흙/풀/자갈/모래 4장을 섞어 칠하는 셰이더(`core/terrain.js`). 질감은 이미 있는 Poly Haven 4종 + 노멀. 가중치: 물가 3m 안 = 자갈·모래, 경사 > 25° = 흙, 평지 = 풀, 야영지 반경 = 밟힌 흙. 준호 자산 필요 없음, 코드만.
**신규 ② 바위 인스턴스** — `world.rockModels: ["../../assets/props/rock_a.glb", …]` → GLB `rock_*` 자리에 랜덤 변형 인스턴스(나무와 같은 길). 준호가 바위 2종 뽑아 주면 즉시.
**신규 ③ 나무 변형** — `treeModels: [oak_a, oak_b, pine_a]` 배열로 확장, 자리마다 변형 랜덤 + LOD(먼 나무는 `oak_a` 6k 판). 준호가 나무 1~2종 더 뽑아 주면 즉시.

## 3. 배우층(신규) — Actor: 「이름·자리·동작」만 받는 사람과 동물

지금: `story.place()` 가 사람을 관절 인형 또는 GLB(대기 동작만)로 세운다. 이동은 `movers`(사슴 달아나기)뿐.
**목표**: 이야기층이 `{ actor: "nuri", go: "hunt", anim: "run" }` 라고만 쓰면 누리가 실제로 뛰어간다.

`core/actor.js`
```
Actor { id, obj(Group), model(GLB clone | 관절인형), mixer, actions{idle,walk,run,sit,point,look}, state, path[], speed }
  play(name, fade=0.25)     // 없는 동작이면 가장 가까운 것으로(sit 없으면 idle)
  goTo([x,z] | areaName, { anim:'walk'|'run', then:'idle'|'sit' })   // groundY 따라 이동, 도착 시 then
  face([x,z] | 'player')    // 몸 틀기(부드럽게)
  tick(dt)                  // 이동·회전·mixer.update, 거리 25m 밖은 mixer 1/3 빈도(LOD)
```
- 사람 GLB 동작 이름 매핑표(Tripo preset): `wait→idle, walk, run, sit_ground/squat→sit, point/wave→point, look_around→look`. manifest 에서 읽는다.
- **군중**: `story.gather(ids, center, radius, anim)` — 여러 배우가 원형으로 걸어와 앉기(불 곁, 사슴 둘레). 지금 `showIf` 로 자리를 바꿔치기하던 것(hana2·hana3…)을 **한 배우가 걸어서 이동**하는 방식으로 대체 — scene.json 의 사람 항목이 반으로 준다(`aru` 하나 + 이동 명령).
- **동물**: `Herd { deer[], state: graze|alert|flee }` — 풀 뜯기(graze 동작 있으면), 경계(고개 듦), 달아남(run + 경로). 사슴 GLB 없으면 지금 소품 사슴에 같은 상태기계만 붙여 둔다(동작은 몸통 흔들기).
- 이야기층 명령(events.do 에 추가): `{actor, go, anim, then}` · `{actor, face}` · `{actor, play}` · `{gather:[…], at, r}` · `{herd:'a', state:'flee', to}`.
- 시험: 가짜 THREE 없이 상태기계만 — `goTo` 뒤 위치·state 전이·`gather` 도착 순서(`tests/test_actor.mjs`).

**준호 자산이 들어오면 자동으로 좋아지는 구조**: 사람 GLB 가 없으면 관절 인형이 같은 명령으로 움직인다(걷기 = 다리 흔들기). 그래서 배우층은 자산과 무관하게 지금 만들 수 있다.

## 9. 저장·리포트층 — SQL 한 장(✋준호 착수 결정 대기)

`sql/setup_kworld_progress.sql`
```
kworld_progress(student_id uuid FK student_profiles, era text, flags jsonb, inventory jsonb, results jsonb,
                hunger real, pos jsonb, updated_at, UNIQUE(student_id, era))
RLS: 학생 본인 행(insert/update/select) · 교사 우리 반 읽기(class_openings 규칙과 같은 헬퍼) · 학부모 읽기(report 규칙)
뷰: report_kworld(학생×시대: act 진행률 = 미션 done 수 / 전체, 발견 수, 확인하기 결과) → 케이학습리포트 R-다음 칸
```
- 클라이언트: `core/save.js` — 깃발이 설 때마다 3초 디바운스 upsert, 미적용/무로그인이면 `localStorage` 로 조용히(케이무비와 같은 태도). 재개: 시작 시 행이 있으면 「이어서 하기 / 처음부터」 카드. 컷신 도중 저장 금지.
- `results`(발굴 확인 2문항) 는 `scores` 표에도 한 줄씩(개념 코드 `hist.paleo.evidence`) — 기존 리포트가 그대로 읽는다.
