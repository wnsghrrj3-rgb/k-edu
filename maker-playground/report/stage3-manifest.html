목표: 템플릿을 코드가 아니라 데이터로 정의하는 시스템. Builder UI·Theme Editor 없음(다음 단계). 스택은 기존 프로젝트 기술 우선 조항에 따라 바닐라 JS 유지(React 미사용 — Manifest 는 JS Object).

1. 계층 구조 (지시서 원칙 준수)

Template → Composition → Scene → Layout → Animation → Theme → Project
· Scene 은 Layout·Animation·Transition 을 Registry 참조만 한다
· Theme 은 색·타이포·전환만 — Scene 을 모른다 (교차 오염 0 — 테스트로 기계검증)
· Layout 안에 Theme 없음 / Scene 안에 Animation 하드코딩 없음

3. Template Manifest 구조

{ id, version, meta:{ name, category, purpose, tags, thumbnail, preview,
    recommendedMediaCount, recommendedDuration },
  theme, supportedRatios, defaultRatio, audio, defaults,
  scenes:[ { id, role, required, repeatable, usePlan, needs, bg, duration,
             layout:'media-left',      ← Layout Registry 참조
             animation:'fade',         ← Animation Registry 참조
             transition:'fade',        ← Transition Registry 참조
             texts:[{ role, bind, maxCh, maxLines, frame, align }] } ],
  rules:[ … ],       ← 씬 자동 생성 규칙 (아래 §4)
  variants:{ … } }   ← Smart Variant (아래 §5)

4. Rules — "사진 N장 → 씬 구성" 을 데이터로

{ when:{ ratio:'16:9' }, cycle:['media-left','media-right','full-media','framed-center'] }
{ when:{ minMedia:12 }, cycleLen:6, mix:[{ slot:3, layout:'gallery', take:4, minLeft:5 }] }
{ pairByRatio:{ '9:16':'stack', '4:5':'stack' }, default:'split' }
{ caption:{ demoteWithout:true, promoteWith:true } }   /* 캡션 없으면 캡션형 회피·있으면 승격 */
{ noRepeatRun:2 }                                       /* 같은 레이아웃 3회 연속 금지 */

compileRules() 가 이 데이터를 mediaPlan 함수로 컴파일한다. if(media>10) 류 하드코딩은 엔진 어디에도 새로 들어가지 않았다 — 아래 시연에서 14장 입력 시 gallery 4장 묶음이 규칙 데이터만으로 발동한다.
